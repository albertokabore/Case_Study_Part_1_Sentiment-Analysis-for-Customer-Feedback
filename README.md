# Sentiment Analysis for Customer Feedback (Airline Industry)

Case Study Part 1. This project classifies customer tweets about US airlines as **negative, neutral or positive** and compares classical machine learning (Naive Bayes, Logistic Regression, Linear SVM) with a BiLSTM RNN. DistilRoBERTa Transformer code is an optional extension; completed Transformer results are not currently available. The results are interpreted in terms of complaint review and customer-experience monitoring.

## Dataset

[Twitter US Airline Sentiment](https://www.kaggle.com/datasets/crowdflower/twitter-airline-sentiment) (CrowdFlower / Figure Eight, 2015): about 14,600 tweets to six US airlines from February 2015, labelled by human annotators with sentiment, annotator confidence and, for negative tweets, the complaint reason. `Tweets.csv` is included in the project root. `database.sqlite` holds the same data in SQLite form and is not used by the code.

Cleaning (documented in `src/data_loading.py`) removes duplicate tweet IDs, keeping the most confident label, and corrects the airline column where *Delta* rows are actually addressed to *@JetBlue*.

## Setup

Requires **Python 3.10–3.12**. The project was developed on Python 3.11, Windows 11, CPU only.

```bash
python -m venv .venv
# Windows: .venv\Scripts\activate      macOS/Linux: source .venv/bin/activate
pip install -r requirements.txt
```

The NLTK resources (stop words, WordNet, POS tagger) are downloaded automatically the first time the preprocessor runs. The DistilRoBERTa weights (~330 MB) are downloaded from the Hugging Face Hub the first time the Transformer stage runs.

## How to run

### Option A: the notebook (recommended for reading)

```bash
jupyter notebook notebooks/sentiment_analysis.ipynb
```

Run all cells. By default the notebook:

* refits each classical model with the hyper-parameters selected by the grid search (stored in `results/metrics/models/*.json`), which takes about a minute;
* loads saved BiLSTM test predictions from `results/predictions/`; Transformer predictions are included only if they exist.

Set `RUN_GRID_SEARCH`, `TRAIN_BILSTM` or `TRAIN_TRANSFORMER` to `True` in the first code cell to re-run those steps in the notebook.

### Option B: the full pipeline (runs a new experiment from scratch)

```bash
python scripts/run_pipeline.py                      # all stages
python scripts/run_pipeline.py --skip-transformer   # everything except the slow Transformer stage
python scripts/run_pipeline.py --stages evaluate insights   # re-run only some stages
```

| Stage | Output | Approx. time (laptop CPU) |
|---|---|---|
| `eda` | summary tables and exploratory figures | 1–2 min |
| `classical` | grid-searched NB / LR / SVM / Word2Vec models and test predictions | ~20 min |
| `ablation` | 5-fold CV contribution of each preprocessing step | ~2 min |
| `rnn` | BiLSTM with early stopping | ~10 min |
| `transformer` | DistilRoBERTa fine-tuning, 3 epochs | ~1 h (minutes on a GPU) |
| `evaluate` | `model_comparison.csv`, per-class metrics, McNemar tests, confusion matrices, ROC curves | <1 min |
| `insights` | key terms, airline Net Sentiment Score, triage operating points, error analysis | <1 min |

Stages communicate only through files in `results/` and `models/`, so any stage can be re-run on its own. Useful options:

* `--n-jobs N`: parallel CV workers. Each needs about 1 GB of RAM; keep the default of 2 on an 8 GB machine.
* `--models lr_tfidf svm_tfidf`: re-tune only selected classical models.
* `--transformer-epochs N`: change the number of fine-tuning epochs.

> **Memory note:** the Transformer stage needs about 3 GB of free RAM. Run it on its own, without other training jobs or the notebook running at the same time: `python scripts/run_pipeline.py --stages transformer evaluate insights`.

### Rebuilding the research paper

```bash
python scripts/build_report.py --author "Your Name" --course "Course" --instructor "Instructor"
```

Reported metrics, tables and figures are generated from `results/`, so re-run this after the pipeline (for example once the Transformer stage has finished) to keep the paper in sync. DistilRoBERTa results are included automatically when they exist.

### Tests

```bash
pytest -q
```

## Reproducibility

* One random seed (`config.SEED = 42`) is set for Python, NumPy, PyTorch, the data split, CV folds, Word2Vec (single worker) and every model.
* The test set (15%, stratified) is held out from model parameter fitting. Business diagnostics reuse it; test-selected triage thresholds are exploratory. Classical models are tuned with 5-fold CV on train + validation; neural models use the validation set for early stopping.
* Vectorisers are fitted inside each CV fold through scikit-learn `Pipeline`s, so predictive vocabulary and IDF weights are not fitted on held-out folds. Repeated texts across the development and test splits remain a separate limitation.
* `results/metrics/split_assignment.csv` records which split every tweet belongs to.
* The notebook checks that its refitted classical models reproduce the saved pipeline predictions.

## Results

The final metrics are in `results/metrics/model_comparison.csv` (accuracy, macro and weighted precision / recall / F1, ROC-AUC and 95 % bootstrap CIs) and `results/metrics/per_class_metrics.csv`. All figures used in the research paper are in `results/figures/`.

## Research review and reproducibility limits

See [reports/Assignment_Review.md](reports/Assignment_Review.md) for assignment coverage, verified findings and submission items. Run `python scripts/audit_project.py` to verify saved splits, labels, counts and metrics without training or adding data. Audit output: `results/metrics/research_audit.json`.

The saved experiment contains six configurations (four algorithm families). Saved LR TF-IDF and word+character SVM search counts differ from current code grids. Historical grids are unavailable; future tuning runs record them. Rerunning the full search is a new experiment and may change scores.

There are 13 distinct lowercased texts shared by test and development; grouped/temporal evaluation remains future work. Classical models fit on 85%, neural models on 70%; training-data budgets differ. Holm-adjusted McNemar tests compare paired error rates, not macro-F1, and are exploratory because the comparator is ranked on the test set.

Set the hash seed before starting Python or Jupyter; setting it inside a running interpreter cannot change that interpreter's hash seed. In PowerShell:

```powershell
$env:PYTHONHASHSEED = "42"
python scripts/run_pipeline.py --skip-transformer
```

Use the same library versions and hardware for exact comparisons. Word2Vec initialization depends on hashing even with one worker. Notebook refits warn if predictions differ.
